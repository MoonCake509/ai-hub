# AI-Hub — серверная платформа агентов

Платформа-оркестратор для программного доступа к агентам (Codex, OpenClaw, Hermes, Qwen, Ollama).
Шлюз — LiteLLM, ядро — hub-agent, доступ — веб-UI. Реализация по ROADMAP v2.

## Где развёрнуто

- Сервер: `win-v76qc2g60q1`, Windows 10 Pro 19045, i5-4430 (4/4), 32 ГБ RAM.
- Рабочее пространство: **`R:\AI-Hub`** (этот каталог).
- Linux-среда: WSL2, дистрибутив **AIHub** (Ubuntu 24.04 LTS), диск `R:\WSL\AIHub`.
- Доступ: LAN `192.168.31.95`, Tailscale `100.104.134.6`.

## Почему рабочее пространство на R:

Физические диски сервера:

- **Диск 0 — WDC WD10EZEX-08RKKA0, 932 ГБ, SATA HDD 7200 rpm (основной).**
  Разделы: `C:` 196 ГБ (свободно 32.8 ГБ — система Windows), `R:` 735 ГБ (свободно 220.8 ГБ).
- **Диск 1 — HGST HTS545050A7E680, 466 ГБ, SATA HDD 5400 rpm (ноутбучный, медленный).**
  Раздел: `D:` 465 ГБ (свободно 299.5 ГБ).
- `F:`, `G:` — USB-картридеры, пустые.

Причины выбора `R:`:

1. `R:` — раздел **основного** диска, того же, где система. Он не отключается и не зависит от внешних/дополнительных накопителей.
2. `C:` не подходит: свободно 32.8 ГБ. Один WSL-vhdx + слои Docker-образов (Postgres, LiteLLM и др.) съедят этот запас и положат систему.
3. `D:` не подходит: это второй, более медленный диск (5400 rpm). Рабочее пространство и виртуальные диски на нём дадут просадку I/O на сборках и БД, а также привяжут проект к состоянию второго накопителя.

Поэтому и рабочее пространство (`R:\AI-Hub`), и виртуальный диск WSL (`R:\WSL\AIHub`) размещены на основном диске.

## Особенности окружения

- **`C:\Windows\System32\wsl.exe` неисправен** — на любую команду возвращает «Отказано в доступе».
  Рабочий бинарь: **`C:\Program Files\WSL\wsl.exe`**. Все скрипты используют полный путь.
- Установка дистрибутива из каталога Microsoft падает с `WININET_E_INVALID_SERVER_RESPONSE`
  (канал рвёт соединения к CDN). Рабочий способ: скачивание rootfs с `cloud-images.ubuntu.com`
  + `wsl --import`.
- Крупные загрузки на сервере обрываются — качать только с докачкой (`curl -C -`) и сверкой размера.
- Внутри WSL рабочее пространство доступно как `/mnt/r/AI-Hub`, из Windows — `R:\AI-Hub`.

## Веб-интерфейс

`http://192.168.31.95:8000/ui/` — статика из `web/`, отдаётся тем же контейнером `hub`
(каталог смонтирован, пересборка не нужна). Первый вход — токен хаба (`HUB_TOKEN` из `infra/.env`),
он хранится только в `localStorage` браузера и уходит в заголовке `Authorization`.

Что умеет:

- реестр агентов с их статусом (`verified` / `unverified`) и транспортом;
- запуск задания: агент, промпт, таймаут → `202` и карточка задания сразу открывается;
- история: фильтр по статусу, время, агент, длительность, число попыток, превью промпта;
- карточка задания: статус, таймаут, признак сверки, вывод, попытки (воркер, время, токены),
  таймлайн событий (`queued → leased → succeeded`, `cancel_requested`, `lease_expired`);
- отмена: в очереди — сразу `cancelled`; в работе — `cancel_requested` с честной пометкой,
  что агент остановку не подтверждает;
- автообновление: список раз в 5 с, открытая карточка раз в 2 с, пока задание активно.

Файлы: `web/index.html`, `web/styles.css`, `web/app.js` — без сборки и зависимостей.

## Задания (async)

Запуск асинхронный: долгий HTTP не держится, обрыв связи не теряет результат.

```
POST /agents/{id}/run
  {"prompt": "...", "timeout": 300, "idempotency_key": "любая-строка"}
  -> 202 {"job_id": "...", "status": "queued", "created": true}
```

- `GET /jobs/{id}` — состояние, попытки, вывод: `queued | running | succeeded | failed | cancelled | timeout | unknown`.
- `GET /jobs?limit=50&status=` — история прогонов (Postgres, схема `aihub`).
- `POST /jobs/{id}/cancel` — отмена (queued → cancelled; running помечается, результат отбрасывается).

Гарантии:

- **Идемпотентность.** Тот же `idempotency_key` с тем же телом возвращает тот же `job_id`
  (`created: false`); с другим телом — `409`.
- **Аренда.** Воркер берёт задание в аренду (`LEASE_SECONDS`, по умолчанию 300) и продлевает её
  heartbeat-ом. Если связь пропала дольше аренды, попытка и задание становятся `unknown`
  с `needs_reconcile: true` — **автоматического повтора нет** (агент мог успеть выполнить работу).
- **Outbox.** Воркер сначала пишет результат в локальный `outbox/`, затем досылает его до
  подтверждения хаба; после перезапуска недосланное отправляется повторно.
- **Рестарт хаба** не теряет задания: очередь и история в Postgres.

Таблицы: `aihub.jobs`, `aihub.job_attempts`, `aihub.job_events` (события `created`, `leased`,
`lease_expired`, `finished`, `cancelled`).


## Эксплуатация: бэкапы, лимиты, история

**Резервные копии.** `tools/backup.sh` делает `pg_dump -Fc` схемы `aihub` в `R:\AI-Hub\backups`,
рядом кладёт `.sha256`, хранит 7 последних дампов. Задача планировщика `AIHub-Backup` — ежедневно в 03:00
(`wsl -d AIHub -e bash /mnt/r/AI-Hub/tools/backup.sh`). Копия вне сервера: ноутбук забирает свежий дамп
задачей `AIHub-Backup-Pull` в 03:30 в `C:\Users\lavy\AI-Hub-backups` и сверяет sha256.

**Проверка восстановления.** `tools/restore_check.sh` разворачивает последний дамп в отдельную БД
`aihub_restore`, сравнивает количество строк в `jobs`, `job_attempts`, `job_events` и последнюю запись,
затем удаляет временную БД. Рабочая база не изменяется.

**Лимиты** (переменные `.env`, значения по умолчанию):

| Переменная | По умолчанию | Что ограничивает |
|---|---|---|
| `MAX_PROMPT_CHARS` | 20000 | длина промпта, иначе `413` |
| `MAX_QUEUE` | 50 | число заданий в статусе `queued`, иначе `429` + `Retry-After: 30` |
| `MAX_RESULT_CHARS` | 100000 | длина сохраняемого вывода; хвост заменяется пометкой «усечено хабом» |
| `LEASE_SECONDS` | 300 | аренда задания воркером (heartbeat продлевает) |

Повтор с тем же `idempotency_key` при заполненной очереди возвращает существующее задание, а не `429`.

**История.** `GET /jobs?limit=&offset=&status=` возвращает `total`, `has_more`, `limit`, `offset`.
В интерфейсе первая страница — 50 записей, кнопка «Показать ещё» догружает следующую.


## HTTPS

Второй контейнер `aihub-hub-tls` поднимает тот же хаб по TLS на `https://192.168.31.95:8443`
(сертификат самоподписанный, лежит в `infra/certs/`, SAN: `192.168.31.95`, `127.0.0.1`, `localhost`).
Порт 8443 проброшен portproxy и открыт в брандмауэре скриптом `C:\Users\user\bin\aihub-net.ps1`
(он же выполняется при входе задачей `AIHub-Net-OnLogon`, поэтому проброс не теряется после перезагрузки).

Первый вход в браузере показывает предупреждение сертификата: «Дополнительно» → «Перейти на 192.168.31.95 (небезопасно)».
Чтобы убрать предупреждение, установите `infra/certs/hub.crt` в «Доверенные корневые центры сертификации».

Плейн-HTTP на `:8000` оставлен для воркеров (`127.0.0.1`) и как резервный вход в локальной сети.
Токен в нём идёт открытым текстом — для постоянной работы используйте `:8443`.
