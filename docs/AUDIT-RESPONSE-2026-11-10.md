# Ответ на независимый аудит 2026-11-10

Аудит признал работу принятой частично. Ниже — что сделано по каждому пункту и чем это подтверждено. Прод на момент аудита не менялся; все изменения ниже выложены после проверки на изолированном стенде.

## 1. Исчезновение данных (59 чатов и 132 задания → 0)

**Причина.** Том базы был объявлен в compose как `pgdata` без фиксированного имени. Docker подставляет имя проекта, поэтому `docker compose -p aihub up` создал новый пустой том `aihub_pgdata` вместо существующего `infra_pgdata`. Сервис поднялся с чистой базой; старые строки остались в прежнем томе, но хаб их больше не видел.

**Что сделано.**
- Прежние данные найдены в томе `infra_pgdata` (контейнер `aihub-core03-infra-copy-pg`): 59 чатов, 132 задания, 5 вложений, 4 проекта.
- Слито с текущей базой аддитивно: текущие строки не перезаписывались, конфликты сохранены в `recovery.conflicts` (2 записи `workers/current_worker_state_preserved` — состояние воркеров намеренно оставлено текущим), каждое действие в `recovery.audit` (2632 записи).
- Итог в проде: **59 чатов, 214 заданий, 5 вложений, 6 проектов**, все 5 вложений читаются.
- Имя тома зафиксировано (`name: aihub_pgdata`), поэтому запуск с любым `-p` теперь использует один и тот же том. Проверено: `docker compose config` даёт одинаковое имя для `-p aihub` и `-p someother`.
- Резервные копии до и после: `backups/aihub-20261110-203349.dump`, `backups/aihub-20261110-204438.dump`; исходный том не удалялся.

**Проверка целостности.** 10 внешних ключей в `aihub`; сирот нет: `jobs→projects` 0, `messages→conversations` 0, `attempts→jobs` 0. Через API: проект «UI-приёмка раскладки» отдаёт 55 чатов, «Проверка поставки» — 4.

## 2. Потеря аренды не останавливает файлового исполнителя

- Heartbeat теперь сверяет поколение ресурсной аренды: чужое или устаревшее поколение → `ok:false`, и воркер обязан прекратить работу (`tests/test_core03_api.py`).
- Аренда checkout при неопределённом исходе переводится в `lease_until='infinity'`: TTL сам по себе больше не открывает дерево второму писателю.
- `apply_patch` ведёт журнал: состояние `uncertain` при частичном применении, бэкап перезаписанных файлов, повтор по `job_id` не применяет патч дважды.

## 3. Частичный результат без квитанции

- Receipt привязан к попытке (`attempt_id`, уникальный индекс) и неизменяем: повтор с другим job/attempt/args/status отвергается с 409, а не перезаписывает первую запись.
- Неопределённый эффект фиксируется как `unknown` в попытке, задании и receipt; событие `execution_uncertain`. Поздний артефакт кладётся в `late_results` и не меняет статус задания.
- Сверка (`/workspace/reconciliation/*`) связывает поздний результат с попыткой только при полном совпадении: job, попытка, ключ идемпотентности, операция, digest аргументов, digest пре-имиджа, корень, applied-список, digest дерева. Иначе — `insufficient`, и «принять исторически» недоступно.
- Решения человека пишутся в `workspace_reconciliation_audit` с ревизией; устаревшая ревизия → 409, гонка двух решений даёт ровно одну запись. Актор — держатель токена хаба, клиентское поле `actor` игнорируется.

## 4. Проверки запускались с правами хоста

- Введён изолированный исполнитель `tools/docker_check_runner.py` (ADR `docs/decisions/CORE-02c-isolated-runner.md`): одноразовый контейнер без сети, read-only rootfs, `cap_drop=ALL`, `no_new_privileges`, nonroot, tmpfs-копия снимка, лимиты CPU/памяти/pids, snapshot монтируется только на чтение.
- Конфигурация — только администраторская (`AIHUB_ISOLATED_RUNNER_ARGV` + JSON с `allowed_roots`, абсолютный путь docker и неизменяемый image ID). Задание не может её изменить.
- Пока исполнитель не настроен, хаб **явно отказывает** в `run_checks` (`runner_unavailable`) — тихого отката к исполнению на хосте нет.
- Проверено живым прогоном: команда не видит контрольный файл вне проекта, не получает переменные окружения хоста, не может писать в исходный снимок и rootfs, не имеет сети; таймаут и очистка контейнера отрабатывают (`tests/test_docker_check_runner.py`, `tests/test_core03_managed_e2e.py`).

## 5. Быстрая проверка каналов не доведена до интерфейса

- Панель быстрой проверки выбранного канала и обновление диагностики — в `web/` (bind-mount, видно сразу): запуск одной кнопкой, бюджет, частичный вердикт, обновление карточек.
- Проверено DOM-тестом `tests/dom-core03-ui.cjs` (`CORE-03 UI DOM/fake-response regressions passed.`).

## 6. Перечисленные проблемы не покрывались тестами

Добавлены тесты, каждый падал бы на прежнем поведении:
- `tests/test_core03_api.py` — unknown/duplicate/late, неизменяемость receipt, пагинация случаев, 409 на устаревшей ревизии, гонка решений, `lease_until='infinity'`.
- `tests/test_core03_managed_e2e.py` — реальный воркер + изолированный runner: inspect → snapshot → run_checks → apply_patch.
- `tests/test_docker_check_runner.py` — границы изоляции и таймаут.
- `tests/dom-core03-ui.cjs` — панель сверки и быстрая проверка.

## Что осталось за пределами этой поставки

- Ноутбучный воркер нужно запускать с `AIHUB_ISOLATED_RUNNER_ARGV`, иначе `run_checks` будет честно отказывать. Это операционное действие на машине воркера, а не код.
- Фоновые процессы CORE-03 (`core03_stage_worker`) и стенд `:8202` — отдельные от прода и оставлены как есть для повторных прогонов.
