# Дизайн AI Hub — персональный эталон проекта

Владелец утвердил этот вид 14.11.2026 словами «стало выглядеть сильно красивее».
Это **не рекомендация**, а обязательный стиль проекта. Любой агент (Codex, Qwen, Hermes,
Claude, OpenClaw) при изменении `web/` обязан сохранять его и не возвращаться к плоскому
одноцветному тёмному интерфейсу.

Источник истины — `web/styles.css`: палитра в `:root`, блок `/* THEME-3 */`, правила
компонентов. Этот документ объясняет **замысел**, CSS задаёт **значения**. При расхождении
побеждает `styles.css`, а документ обновляется в том же коммите.

## 1. Впечатление, которое нужно сохранять

Тёмная «приборная панель» с цветовым объёмом: почти чёрная сцена, слоистые поверхности,
бирюзовый акцент и фиолетовый контровой свет. Владелец читает картинку целиком, а не
метрики контраста, поэтому проверка «контраст ≥ 3:1» **не является приёмкой**. Приёмка —
визуальное «да, красиво» от владельца плюс скриншот до/после.

Запрещено:
- монотонный серо-синий интерфейс без акцентных зон и градиентов;
- тонкие невидимые границы и одинаковые по яркости панели;
- возврат к «плоскому» фону `#10141c` без радиальных подсветок;
- декоративные анимации, мешающие работе, и анимации при `prefers-reduced-motion: reduce`.

Правила цвета:
- акцент — один смысл: «здесь действие или активное состояние»;
- золото только у оркестратора, никогда у обычных ролей;
- ошибки красным, успех зелёным, предупреждения янтарным — не смешивать;
- фиолетовый и синий — свет и иерархия, не статусы.

## 3. Свет и поверхности

`body` держит два радиальных градиента: бирюзовый сверху-слева, фиолетовый сверху-справа,
поверх `--bg`. Шапка — тонкая бирюзово-фиолетовая полоса по нижней границе. Панели не
плоские: вертикальный градиент от `--surface` к `--panel`, граница `--line`, внутренняя
тень `inset 0 1px 0 rgba(255,255,255,.05)`.

Иерархия: сцена → панель → поверхность → приподнятая поверхность. Активный элемент
поднимается на ступень и получает левую акцентную полосу 2px.

## 4. Типографика и плотность

- Заголовки панелей — 15–16px, вес 600, letter-spacing −0.01em.
- Надзаголовки (`eyebrow`) — 10px, uppercase, letter-spacing 0.12em, цвет `--faint`.
- Основной текст 12.5–13px, подписи 10.5–11px, числа — `font-variant-numeric: tabular-nums`.
- Радиусы: 8px у полей и небольших карточек, 10–12px у панелей, 999px у пилюль.
- Отступы кратны 4: 4/8/12/16/24.

## 5. Компоненты

- **Кнопки.** Основная — заливка `--accent`, текст `--accent-ink`, свечение
  `0 6px 18px rgba(53,220,242,.22)`. Вторичная — прозрачная с границей `--line-strong`.
  Наведение поднимает яркость, фокус — кольцо `0 0 0 2px rgba(53,220,242,.35)`.
- **Поля.** Фон `#0a141f`, граница `--line`, фокус — граница `--accent`.
- **Карточки ролей.** Слева цветная полоса роли. Оркестратор — постоянная рамка
  `2px solid #d8ae3f`. Текущий получатель — заливка карточки, а не только рамка.
- **Скрепка и вложения.** Загрузка файла — скрепка у строки ввода. Файл попадает в
  `Загрузки` рабочей папки проекта, а не в отдельное нижнее меню.
- **Правая колонка.** Две страницы на одном месте: «Воркеры» (назначения, редактор роли,
  лимиты, расписание) и «Файлы» (контекст проекта и последние 20 загрузок). Переключение —
  сегментированные вкладки, без перезагрузки страницы.
- **Вкладка «Расход».** Токены по времени: 24 часа по часам, 7/30 дней по дням; фильтры
  по провайдеру и модели; срезы по моделям и провайдерам; столбики с подсказкой значения.

## 6. Движение

- Появление панелей — 160–200ms `ease-out`, сдвиг на 4–6px.
- Меню выбора — 180ms, Popover API, без «прыжка» раскладки.
- Создание рабочей зоны проекта — пошаговый прогресс с плавной анимацией, пока идёт запрос.
- Все переходы отключаются при `prefers-reduced-motion: reduce`.

## 7. Приёмка UI

1. Изменение видно в браузере на стенде, а не только в CSS-метриках.
2. Скриншот до/после приложен к отчёту владельцу.
3. Владелец сказал «да», а не «стало тускло».
4. `node --check web/app.js` и `npx modern-web-guidance legacy-scan web` чистые.
5. Контраст проверяется как минимум, но не подменяет визуальную оценку.
