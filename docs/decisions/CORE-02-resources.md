# CORE-02a. Аренды ресурсов: один checkout — один писатель

**Дата:** 2026-11-10 · **Статус:** принято и реализовано (первая половина CORE-02)

## Вопрос

Два задания могли одновременно писать в один и тот же рабочий каталог: хаб выдавал
аренду задания, ничего не зная о том, что каталог уже занят. Один CDP, доступный
через два имени агента, тоже считался двумя разными ресурсами, поэтому «лимит»
обходился переименованием. Отдельно нужен признак поколения: после освобождения
ресурса поздний результат старого держателя не должен выглядеть актуальным.

## Решение

**Ключ строится из адреса, а не из имени.** `checkout:<host>:<canonical path>`,
`cdp:<host>:<ip:port>`, `cli:<host>:<binary>`, `model:<host>:<server>`.
Канонизация: путь — обратные слэши, нижний регистр, без хвостового слэша; `..`
отвергается; `localhost`/`::1`/`0.0.0.0` сводятся к `127.0.0.1`, порт обязателен.
Поэтому `openclaw` и `qwen`, смотрящие в один browser на `127.0.0.1:9333`, — один
ресурс.

**Аренда берётся в транзакции аренды задания.** `db.lease_job` после выбора задания
вставляет аренду checkout; если каталог занят живой арендой другого задания —
транзакция откатывается, задание остаётся `queued`, воркер не получает второго
писателя. Задание без проекта и рабочего каталога checkout не занимает: писать ему
некуда.

**Поколение (fencing).** При каждой новой аренде `generation` растёт. Освобождение
не удаляет строку, а помечает её (`released_at`, `lease_until = now()`, `job_id = null`):
иначе следующая аренда получила бы поколение 1 и старый держатель снова выглядел бы
актуальным. Это же поколение нужно будущим `workspace.apply_patch`/`run_checks`
(CORE-02b), чтобы отклонить патч от устаревшей аренды.

**Освобождение только по владельцу.** `POST /resources/release` требует и ключ, и
`job_id`; чужое задание аренду не снимет. Автоматически аренды освобождаются в
`finish_attempt`, `cancel_job`, `expire_leases` и подметаются `resources.sweep()`
раз в тик sweeper.

## Границы

- Это первая половина CORE-02: сами операции `workspace.inspect/snapshot/read/apply_patch/
  run_checks/package` на устройстве и проверяемая изоляция тестовой среды — следующий шаг
  (CORE-02b). Аренда без них уже полезна: она не даёт двум писателям сойтись в одном каталоге.
- Ожидание ресурса не реализовано: занятый каталог означает «задание ждёт в очереди»,
  а не «ждём до N секунд». При длинной очереди в занятый каталог возможен простой головы
  очереди — это осознанно оставлено на CORE-02b (справедливая выборка по свободным ключам).
- Аренды CDP/CLI/модели пока не выдаются автоматически: ключи и API готовы, привязка к
  конкретным адаптерам — вместе с матрицей возможностей ADAPTER-01.

## Проверено

- Юнит: 12 проверок (`tests/test_core02_resources.py`) — один путь в пяти написаниях даёт
  один ключ, разные host/пути/порты — разные ключи, `..` и пустой путь отвергаются,
  `localhost` и `127.0.0.1` совпадают, два alias одного endpoint делят ресурс.
- Живой контракт стенда: 16 проверок (`tests/test_core02_api.py`) — проект с рабочим
  каталогом, два задания в него, аренда взяла `checkout:…` с поколением 1, второму
  исполнителю каталог не выдан, чужое освобождение отклонено, после закрытия задания
  ресурс освобождён, второе задание получило тот же ключ с поколением 2.
- Регресс: CORE-01 (22 и 9 проверок) и полный контракт (51 проверка) — без падений.
