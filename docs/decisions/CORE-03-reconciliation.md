# CORE-03: сверка неопределённых и поздних результатов

**Статус:** принято 2026-11-10. Заменяет прежнее правило «поздний результат тихо игнорируется».

## Проблема

После потери аренды исполнитель может продолжать работу: файловая операция уже применилась, а хаб об этом не знает. Прежняя модель хранила поздний результат в `late_results`, но не давала способа безопасно связать его с попыткой и не мешала второму писателю зайти в тот же checkout по истечении TTL.

## Решение

1. **Неопределённость — отдельный исход.** Воркер, потерявший уверенность в эффекте, присылает `uncertain=true`. Хаб закрывает попытку и задание статусом `unknown`, ставит `needs_reconcile=true` и пишет событие `execution_uncertain`. `unknown` никогда не превращается в `succeeded` сам по себе.
2. **Checkout не освобождается по TTL.** При `unknown` аренда ресурса получает `lease_until='infinity'`. Второй писатель в это дерево не зайдёт, пока человек не разрешит случай.
3. **Receipt неизменяем.** `workspace_receipts` получает `attempt_id` (уникальный индекс) и статусы `pending|applied|failed|unknown|late`. Повтор с другим job/attempt/args/status отвергается (`workspace_receipt_*_conflict`), а не перезаписывает первую запись.
4. **Поздний результат не переписывает историю.** `late_results` уникален по `attempt_id`; повторное вложение с тем же содержимым — `late`, с другим — конфликт.
5. **Связывание только по полному совпадению.** Случай считается подтверждённым (`linked_worker_artifact`), если совпали: job, попытка, ключ идемпотентности, операция, digest аргументов, digest пре-имиджа, корень, applied-список и digest дерева. Иначе провенанс `insufficient`, и действие `accept_historical` недоступно.
6. **Решение человека — аудит, а не перезапись.** `workspace_reconciliation_audit` хранит `(case_id, revision)` с действием, актором, основанием и снимком доказательств. Повтор того же решения идемпотентен, устаревшая ревизия — `409`, гонка двух решений даёт ровно одну запись. Актор — держатель токена хаба, клиентское поле `actor` игнорируется.

## API

- `GET /workspace/reconciliation/cases` — курсорная пагинация по `(event_at, case_id)`, фильтры `decision_state` и `job_status`.
- `GET /workspace/reconciliation/cases/{case_id}` — карточка, доказательства и история решений.
- `POST /workspace/reconciliation/cases/{case_id}/decision` — `{action, expected_revision, reason}`; `action ∈ {accept_historical, reject}`.

## Проверено

- `tests/test_core03_api.py` — живой контракт на изолированном стеке: unknown → duplicate → late, неизменяемость receipt, пагинация, 409 на устаревшей ревизии, гонка решений, `lease_until='infinity'`.
- `tests/test_core03_managed_e2e.py` — реальный воркер и настоящий изолированный Docker-runner: inspect → snapshot → run_checks (сеть off, rootfs ro, nonroot) → apply_patch.

## Отклонено

- Автоматическое принятие позднего результата по времени — не доказывает, что эффект применён именно этой попыткой.
- Освобождение checkout по истечении аренды при `unknown` — открывает второго писателя в дерево с неизвестным состоянием.
