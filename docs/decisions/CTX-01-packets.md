# CTX-01: пакеты артефактов

**Статус:** принято 2026-11-10.

## Проблема

Задание получало «файлы проекта» как договорённость на словах: какие именно версии вошли во вход, чем подтверждён их хеш и почему часть файлов не попала — нигде не фиксировалось. Изменение файла между показом и запуском обнаруживалось только по факту странного результата.

## Решение

1. **Пакет — это зафиксированный набор файлов с версиями.** Манифест хранит путь, размер и `sha256` каждого файла, а также причину включения или исключения. Пакет собирается по фактическому ответу хоста (`list_files`), а не по догадке хаба.
2. **Digest по каноническому манифесту.** Считается по выбранным файлам, отсортированным по пути: `path|size|sha256`. Одинаковый набор даёт одинаковый digest независимо от порядка обхода; изменение содержимого, размера или бюджета меняет digest.
3. **Бюджет объясняется.** Файлы сверх `budget_bytes` не отбрасываются молча — у каждого причина «не влезло в бюджет N байт». Не запрошенные — «не запрошен», из служебного каталога — «служебный каталог».
4. **Секреты не покидают хост.** `.env*`, ключи, `auth.json`, `credentials*`, `id_rsa*` и подобные исключаются всегда, даже если запрошены явно; абсолютные пути и `..` отвергаются.
5. **Сверка вместо доверия.** `recheck` заново собирает пакет с хоста: совпало — пакет остаётся прежним; изменилось — новая ревизия со статусом `conflict` и сохранённым прежним digest.
6. **Материализация на хосте.** `materialize` создаёт управляемый снимок проекта под пакет; его digest хранится рядом с digest пакета, чтобы потребитель мог сверить, что снимок соответствует зафиксированному входу.

## API

- `POST /projects/{project_id}/context/packets` — `{paths, budget_bytes, conversation_id?}` → 202, `packet_id`.
- `GET /projects/{project_id}/context/packets` — список пакетов проекта.
- `GET /context/packets/{packet_id}` — манифест, причины, digest, состояние, ревизия.
- `POST /context/packets/{packet_id}/recheck` — сверка с фактическим состоянием.
- `POST /context/packets/{packet_id}/materialize` — снимок на хосте.

Состояния: `probing` → `sealed` | `conflict` | `failed`; `materializing` → `materialized`.

## Проверено

- `tests/test_ctx01_packets.py` — 16/16 в образе хаба: отказ на абсолютных путях и `..`, секреты не выбираются даже при явном запросе, бюджет исключает с причиной, digest стабилен к порядку и меняется от содержимого и бюджета, `safe_join` не выпускает за корень.
- Живой стенд CORE-03 с реальным воркером: пакет собрался (`sealed`, ревизия 1), внутрь вошли только `src/a.py` и `docs/readme.md`, `.env` и `node_modules` не попали; повторная сверка без изменений — `sealed`, ревизия 1 (ложного конфликта нет); после изменения файла — `conflict`, ревизия 2.

## Отклонено

- Считать список файлов на стороне хаба — он не видит диск хоста и начал бы выдумывать содержимое.
- Молча обрезать пакет по бюджету — «почему этого файла нет» должно быть в манифесте.
- Разрешать секретные пути по явному запросу — запрос приходит из модели, а не от администратора.
- Хранить только digest без манифеста — тогда нельзя объяснить состав и нельзя восстановить вход.
