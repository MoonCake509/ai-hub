# CTX-02: сборщик контекста и краткая память

**Статус:** принято 2026-11-10.

## Проблема

Задание на один модуль получало весь проект: точку входа, все импорты и всю историю. Большой обязательный контракт при этом мог молча обрезаться, а «почему этих файлов нет» никто не объяснял.

## Решение

1. **Сборка под задачу, а не под проект.** На вход подаётся цель, точка входа и список обязательных контрактов. Собираются: контракты целиком, точка входа, её прямые импорты (разбор `from . import x` / `require('x')`, разрешение в файл проекта), затем файлы, совпавшие по словам цели.
2. **Контракт не обрезается.** Если обязательные контракты не влезают в бюджет — ошибка `contract_exceeds_budget` с точными числами, а не тихое усечение.
3. **Оценка токенов.** Считается по размеру файла (≈4 символа на токен) до чтения содержимого; в ответе есть `used_tokens`, `total_project_tokens`, `saved_tokens`, `saved_ratio` — фактическое сокращение, а не обещание.
4. **У каждого файла причина.** «обязательный контракт», «точка входа», «прямой импорт», «по цели задачи», «не влезло в бюджет N токенов».
5. **Версия и инвалидация.** Digest считается по выбранному набору; повторная сверка с прежним digest даёт `sealed`, изменение — `conflict` и новую ревизию.

## API

- `POST /projects/{id}/context/requests` — `{goal, entry, contracts, budget_tokens}` → 202.
- `GET /context/requests/{id}` — состав, токены, экономия, причины, digest, состояние.
- `POST /context/requests/{id}/recheck` — сверка с текущим состоянием проекта.

## Проверено

- `tests/test_ctx02_context.py` — 12/12: оценка токенов, разбор Python/JS импортов, разрешение относительных путей, обязательность контрактов, ошибки на отсутствующем контракте и неизвестной точке входа, отбор под бюджет с причинами, стабильность digest и чувствительность к изменению.
- Живой стенд CORE-03: вход собран в `sealed`, использовано 767 токенов из 1875 (экономия 59%), в набор вошли контракт, точка входа, импорт и два модуля; остальные исключены с причиной «не влезло в бюджет 900 токенов». Повтор без изменений — тот же digest; после правки входа — `conflict`, ревизия 2.

## Отклонено

- Отдавать весь проект «на всякий случай» — это и есть причина раздутого входа.
- Обрезать контракт молча — тогда агент принимает решения по неполному контракту.
- Считать токены после чтения всех файлов — дорого и бессмысленно для отбора.
