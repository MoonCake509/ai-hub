# FLOW-01: durable контроллер запусков

**Статус:** принято 2026-11-10.

## Проблема

Запуск «пяти ролей» существовал как последовательность вызовов в голове оператора: порядок держался на памяти, повторная отправка создавала второе исполнение, а перезапуск хаба стирал представление о том, что уже сделано.

## Решение

1. **Состояние в базе, а не в памяти.** Три таблицы: `runs` (шаблон, версия, политика, состояние), `run_tasks` (ключ, роль, агент, промпт, зависимости, состояние, попытка, задание), `run_events` (журнал: создан, выдано, закрыто, пауза, отмена).
2. **Только готовые задачи.** Задача выдаётся, когда все её зависимости в состоянии `done`; задача с зависимостью от упавшей ветки не запускается.
3. **Идемпотентность через operation key.** Ключ задания — `run:<id>:<шаг>:<попытка>`; повторный `dispatch` не создаёт второе исполнение того же шага.
4. **Управление состоянием.** `pause` запрещает выдачу, `resume` возвращает, `cancel` помечает запуск и все незавершённые задачи отменёнными; отменённый запуск не воскресает.
5. **Шаблон проверяется до старта.** Дубли ключей, неизвестные зависимости, зависимость от себя и циклы отвергаются с кодом, а не падают в процессе.
6. **Самодвижение.** Sweeper закрывает задачи по фактическому статусу задания и выдаёт следующие готовые — запуск продолжается и после перезапуска хаба.

## API

- `POST /runs` — `{project_id, template:{id, version, steps:[{key, role, agent, prompt, depends_on}]}, policy}` → 202.
- `GET /runs/{id}` — состояние, задачи, журнал событий.
- `POST /runs/{id}/dispatch` — выдать готовые задачи.
- `POST /runs/{id}/pause|resume|cancel`.

## Проверено

- `tests/test_flow01_runs.py` — 8/8: цепочка, пустой шаблон, дубли ключей, неизвестная зависимость, зависимость от себя, цикл, шаг без ключа, форма ошибки.
- Живой стенд CORE-03: цепочка `plan → code → review`; первый `dispatch` выдал только `plan`, второй — ничего; при `pause` выдача отклонена с причиной «запуск не активен»; `resume` вернул активность; `cancel` перевёл все три задачи в `cancelled`.

## Отклонено

- Хранить план в памяти процесса — перезапуск хаба теряет прогресс.
- Запускать все шаги сразу — роли зависят друг от друга по результату.
- Считать повторный dispatch безопасным «на всякий случай» — он создаёт второго исполнителя в том же дереве.
