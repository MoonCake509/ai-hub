# FLOW-02: шаблон пяти ролей

**Статус:** принято 2026-11-10.

## Проблема

Один запрос проходил через роли только потому, что человек копировал сообщения между ними. Роли видели общую переписку целиком, а не свой релевантный вход, и переход «проверки провалились → вернуть кодеру» держался на внимании оператора.

## Решение

1. **Пять типизированных ролей.** Планировщик (`tasks`), кодер (`summary`, `files`), тестировщик (`checks`, `ok`), ревьюер (`verdict`, `findings`), архивариус (`summary`, `artifacts`). У каждой роли — обязательные поля выхода.
2. **Переход по правилу, без LLM.** Выход разбирается как JSON (в том числе из ```-блока). Нет обязательных полей — шаг падает с причиной. Тестировщик с `ok=false` и ревьюер с `verdict≠approve` не пропускают дальше; правило возврата указывает на кодера.
3. **Свой вход у каждой роли.** Планировщик получает документацию и контракты, кодер — исходники, тестировщик — тесты, ревьюер — исходники изменения, архивариус — документацию. Для роли создаётся отдельный пакет, его идентификатор уходит в промпт; общей переписки в промпте нет.
4. **Цепочка зависимостей.** `plan → code → test → review → archive`, шаги валидируются контроллером запусков (дубли, циклы, неизвестные зависимости).

## API

- `GET /templates/five-roles?entry=&contracts=` — описание ролей, схем выходов и входов.
- `POST /runs` с `template_id: "five-roles"` — разворачивает шаблон на сервере.

## Проверено

- `tests/test_flow02_templates.py` — 11/11: порядок и зависимости шагов, разные входы ролей, шаблон проходит валидацию контроллера, обязательные поля, отказ на не-JSON, приём JSON в ```-блоке, `ok=false` и `changes_requested` не пропускают, правило возврата к кодеру, неизвестная роль.
- Живой прод: `GET /templates/five-roles` отдаёт пять ролей и пять шагов с разными наборами путей и бюджетами.

## Отклонено

- Давать всем ролям общую переписку — это и есть причина «копирования сообщений человеком».
- Определять переход отдельным LLM-вызовом — дороже и невоспроизводимо; правило по схеме проверяемо.
- Считать любой текст ответом роли — без схемы нельзя отличить «сделано» от «показалось».
