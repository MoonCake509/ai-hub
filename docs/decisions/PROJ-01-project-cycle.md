# PROJ-01 — Создание проекта и цикл разработки: что и почему

**Дата:** 12.11.2026. **Источник:** `AI-Hub-project-workflow.md` (документ владельца).

## Раскладка рабочей папки

Рабочая папка проекта — каталог под `projects.root` (`config/hub.yaml` → `R:\Projects`),
имя `slug-id8`. Внутри два слоя:

- `repo/` — канонический Git-репозиторий (ветка, коммиты, SHA). Git-корень проекта
  указывает именно сюда, поэтому `ops/` не попадает в историю кода.
- `ops/` — живые отчёты рядом с репозиторием: `TASKFLOW.md`, `pr/<шаг>.md`,
  `BACKUPS.md`, `END.md`, `INDEX.md`, `ENVIRONMENTS.md`.

Причина: документ требует и версионируемый код, и рабочие отчёты, которые меняются
на каждом шаге. Смешивать их в одном дереве — значит коммитить шум и терять
восстановимую точку.

## Идемпотентность

- `POST /projects` с `idempotency_key`: повтор возвращает ту же запись и ту же папку.
- `init_project` на хосте не перезаписывает существующие файлы и не делает второй
  коммит, поэтому повтор прерванной подготовки завершает её, а не начинает заново.
- `write_reports`: одинаковое содержимое не перезаписывается (отчёт `skipped`).
- `create_backup`: имя файла без времени (`<label>-<sha8>.zip`), одна точка на коммит.
- `refresh_index`: карта строится по `git ls-tree HEAD`, тот же коммит — тот же файл.
- Задания хаб ставит с ключом идемпотентности; повтор вернёт то же задание.

## Точки восстановления

`create_backup` делает `git archive HEAD` → zip в `ops/backups/`, считает SHA-256,
пишет строку в `ops/BACKUPS.md` (задача, время, SHA, хост, путь, контрольная сумма,
команда восстановления). Если в настройках проекта `backup_required`, `POST /runs`
сначала требует подтверждённую точку и отвечает 409 `backup_unconfirmed` без неё.

## Живые отчёты

`hub/app/reports.py` собирает `TASKFLOW.md` и `pr/<шаг>.md` из фактических задач прогона
(роль, статус, кандидат, проверки). Вызывается после каждого события шага и вручную через
`POST /projects/{id}/reports/sync`. Отчёт не выдумывает данные: чего нет в прогоне, того
нет в журнале.

## Карта проекта

`refresh_index` пишет `ops/INDEX.md` (путь, байты, SHA-256 файла) и обновляет карточку
проекта: `index_sha`, `index_files`, `indexed_at`. Роль архивариуса — это вызов
`POST /projects/{id}/index/refresh` плюс итог в `ops/END.md`.

## Роли

В документе роль называется «архитектор», в коде — `planner` (`ROLE_IDS`, шаблон
`five-roles`). Решение не принято: переименование меняет идентификаторы ролей в
шаблонах и карточках. Предложение — оставить `planner` в коде и писать «архитектор»
в интерфейсе (одна строка отображения), чтобы не ломать данные.

## Проверки

Изолированный исполнитель проверок требуeт Linux (см. `bugs/2026-11-12-runner-unavailable.md`).
До его появления сценарий «задача через FLOW с программными проверками» на этом
Windows-хосте не запускается.
