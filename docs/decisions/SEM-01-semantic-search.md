# SEM-01: семантический поиск по коду и документации

Дата: 12.11.2026. Пункт документа «Создание проекта и цикл разработки в AI Hub», строка 57.

## Что сделано

- Хаб получил таблицу `aihub.semantic_chunks`: проект, коммит, путь, строки, вид
  (`code`/`docs`), текст фрагмента, вектор и адрес модели. Уникальность —
  `(project_id, sha, path, start_line)`, повторная индексация того же коммита заменяет срез.
- Воркер (`semantic_index`) читает файлы **из коммита** (`git ls-tree` + `git show`),
  режет на перекрывающиеся фрагменты (код 40 строк / 8 перекрытия, документы 60/10),
  считает векторы локальным `llama-server` и отправляет их в хаб отдельным запросом
  `POST /projects/{id}/semantic/ingest`.
- Почему не через результат задания: результат обрезается хабом на ~100 КБ
  («усечено хабом»), а индекс из сотен фрагментов больше. Воркер шлёт его сам тем же токеном.
- Поиск: `GET /projects/{id}/semantic/search?q=&limit=&sha=`. Вектор запроса считается
  той же моделью по каждому виду фрагментов, ранжирование — косинус в хабе.
  Ответ содержит путь, строки, версию коммита и текст фрагмента.
- Индекс привязан к коммиту: поиск по старому SHA не подмешивает свежие файлы.

## Отклонение от буквы документа

Документ называет `code_retriever_ru_en` для кода и E5 для документации. В пилоте **обе**
части индексируются E5: модель `code_retriever_ru_en` — ModernBERT, конвертация в GGUF
проходит, но сборка `llama.cpp` 12058 отказывается её грузить
(`key not found in model: modern-bert.attention.layer_norm_epsilon`). Движок не обновляли:
по правилу стека обновление — отдельная обратимая операция с проверкой прежней модели.

Как включить раздельные модели, когда движок научится:

1. `AIHUB_EMBED_CODE_URL=http://127.0.0.1:11441` в окружении воркера.
2. Запустить второй `llama-server` с `D:\llm\models\embed\code-v2.gguf` на 11441.
3. Переиндексировать проект: `POST /projects/{id}/semantic/index`.

## Ограничения пилота

- Векторы хранятся как jsonb и сравниваются в Python: для сотен фрагментов это быстро,
  для десятков тысяч нужен pgvector.
- Индексация запускается вручную (`POST …/semantic/index`); автоматическая — после слияния
  в следующем шаге, вместе с пересборкой карты.
