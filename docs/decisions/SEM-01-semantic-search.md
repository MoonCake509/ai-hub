## Что сделано

- Хаб получил таблицу `aihub.semantic_chunks`: проект, коммит, путь, строки, вид
  (`code`/`docs`), текст фрагмента, вектор и адрес модели. Уникальность —
  `(project_id, sha, path, start_line)`, повторная индексация того же коммита заменяет срез.
- Воркер (`semantic_index`) читает файлы **из коммита** (`git ls-tree` + `git show`),
  режет на перекрывающиеся фрагменты (код 40 строк / 8 перекрытия, документы 60/10),
  считает векторы локальным `llama-server` и отправляет их в хаб отдельным запросом
  `POST /projects/{id}/semantic/ingest`.
- Почему не через результат задания: результат обрезается хабом на ~100 КБ
  («усечено хабом»), а индекс из сотен фрагментов больше. Воркер шлёт его сам тем же токеном.
- Поиск: `GET /projects/{id}/semantic/search?q=&limit=&sha=`. Вектор запроса считается
  той же моделью по каждому виду фрагментов, ранжирование — косинус в хабе.
  Ответ содержит путь, строки, версию коммита и текст фрагмента.
- Индекс привязан к коммиту: поиск по старому SHA не подмешивает свежие файлы.

- Векторы хранятся как jsonb и сравниваются в Python: для сотен фрагментов это быстро,
  для десятков тысяч нужен pgvector.

## Проверяемый контекст для кодера (решение Codex, P-09 вторая половина)

Поиск делает хаб после фиксации `base_sha` и до выдачи шага `code`; кодер сам не ищет.
Найденные фрагменты — отдельный тип evidence, не файлы пакета: сверка preimage рассчитана
на целые файлы, диапазон строк нельзя выдавать за файл.

- Привязка строго к `base_sha` запуска: выборка из индекса этого SHA, переход на `main` запрещён.
- Элемент: `sha`, путь, `start_line`/`end_line`, `kind`, текст, `blob_oid`, sha256 текста, `score`, модель.
- `blob_oid` сверяется с деревом коммита, диапазон и хеш текста — с содержимым blob на хосте
  (операция `verify_evidence`). Несовпавший элемент отбрасывается и в промпт не попадает.
- Векторы запроса считает тот же embedding-воркер той же моделью, что и фрагменты этого вида;
  разные модели не смешиваются.
- Пределы: до 5 фрагментов и до 1500 токенов; пересекающиеся диапазоны дедуплицируются,
  порядок детерминирован (по score, затем путь/строки).
- Evidence входит в digest пакета: смена набора фрагментов — новая ревизия. Права записи
  фрагменты не дают, это справочный контекст.
- Сбои не блокируют запуск: `no_index`, `embed_failed`, `verify_failed`, `empty`, `rejected`
  пишутся в `manifest.semantic`; при отсутствии индекса запуск идёт без фрагментов.
- Побочное: тик `poll_active` защищён от наложения (иначе два прохода по одному пакету
  вставляли дубли items и роняли sweeper).

Проверено: `collect_evidence` на проекте Flow Acceptance, SHA `26e66731`, цель «максимум из
двух чисел» — 5 фрагментов (app.py, tests/test_max.py и др.), 399 токенов, blob_oid и хеши
подтверждены. Тесты: `tests/test_p09_semantic_evidence.py` (8) + прежние P-09, всего 43 passed.
